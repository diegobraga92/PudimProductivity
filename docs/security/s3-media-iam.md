# S3 Media Upload — IAM Policy (Security Review)

> Reviewed 2026-08-09 as part of Phase 5/5a. The backend never proxies upload
> bytes: clients upload **directly to S3 via presigned PUT URLs** generated by
> `internal/media` (see ADR 007).

## Least-privilege bucket policy

The backend's IAM role needs **one** permission: `s3:PutObject` on the media
prefix (nothing else — no ListBucket, no DeleteObject, no GetObject).

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "PresignedUploadsOnly",
      "Effect": "Allow",
      "Action": ["s3:PutObject"],
      "Resource": "arn:aws:s3:::pudim-media/recipes/*"
    }
  ]
}
```

## Presigned URL parameters (backend-controlled)

| Parameter | Value | Why |
|-----------|-------|-----|
| TTL | 15 minutes | Short enough to avoid leaking a write token |
| `ContentType` | required from the client (`upload-url` request body) | Lets S3 reject mismatched content types |
| Object key | `shared.NewUUID() + "/" + sanitized-filename` | Unguessable prefix per upload; filename sanitized to `[A-Za-z0-9._-]` |
| Max object size | 10 MB | Enforced by the **client** (and an S3 bucket lifecycle rule as backstop) |

## Public read model

- `recipes.image_url` stores the **object key**, not a full URL. The web/mobile
  clients prefix it with the public bucket URL
  (`https://pudim-media.s3.amazonaws.com/<key>`), so the bucket stays
  private-write / public-read.
- Alternative: keep the bucket fully private and serve via CloudFront with a
  signed-URL or OAC (Origin Access Control) policy — the recommended posture
  once there is any non-public content.

## Threat model notes

| Threat | Mitigation |
|--------|-----------|
| Presigned URL leaked in logs | TTL 15 min; single-key; `s3:PutObject` only |
| Upload of non-image content | `ContentType` required; bucket lifecycle deletes non-`image/*` after 1 day (backstop) |
| Bucket takeover / misconfig | Bucket policy denies public `s3:PutObject` (only the role's presigns grant time-limited writes); `aws:s3:server-side-encryption` condition recommended |
| Storage abuse (huge files) | 10 MB client cap + lifecycle rule |

## Setup (once)

```bash
aws s3api create-bucket --bucket pudim-media --region us-east-1
aws s3api put-bucket-policy --bucket pudim-media --policy "$(cat media-bucket-policy.json)"
# Backend env:
#   S3_MEDIA_BUCKET=pudim-media
#   S3_MEDIA_REGION=us-east-1
#   AWS_ACCESS_KEY_ID / AWS_SECRET_ACCESS_KEY (role or user with the policy above)
```

If `S3_MEDIA_BUCKET` is unset the backend runs in **degraded mode**: recipe
upload-URL endpoints return 503 and all other functionality is unaffected.
